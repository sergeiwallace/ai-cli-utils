- [x] `[P2]` `[AI-CLI-86]` **Bug: long-running watchers leak zombie child processes (no SIGCHLD reaping)** — FIXED 2026-07-04 (sw-3): reap the `ssh -f` tunnel parent in `messaging._reap_tunnel_parent` (poll, else bounded off-loop wait) on both tunnel-up and never-up paths; guarded `close()` terminate. Did NOT use SIGCHLD=SIG_IGN (watchers also run subprocess.run for git → ECHILD). 6 tunnel tests pass. Original scope: — Each long-running watcher (`ai internal signal-watch`, `ai sync watch`, `ai memory watch`) accumulates one persistent `<defunct>` child. Root cause: the NATS tunnel is spawned via `subprocess.Popen(["ssh", "-fN", ...])` in `messaging.py:71` and only ever `.terminate()`'d at shutdown (line 249) — never `.wait()`'d. `ssh -f` forks to background and the foreground process exits immediately after auth, but Python never reaps it, so it lingers as a zombie for the watcher's lifetime. No `SIGCHLD`/`SIG_IGN`/`waitpid` reaping exists anywhere in the codebase (`grep` confirmed). Harmless (empty proc-table slots, no memory/CPU) and self-clears when each session/watcher exits, but accumulates across live sessions. **Fix options:** (a) install `signal.signal(signal.SIGCHLD, signal.SIG_IGN)` at each watcher entrypoint (`_internal_signal_watch`, `cmd_sync_watch`, `cmd_memory_watch`) so the OS auto-reaps — general, one-liner each; or (b) `.wait()`/`.poll()` the tunnel `Popen` right after `ssh -f` returns (messaging-specific). Recommend (a). Note: takes effect only on watcher restart (i.e. new sessions); existing zombies cannot be reaped externally. Found during zombie-process cleanup 2026-07-03.
