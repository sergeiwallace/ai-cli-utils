- `ai c <name>` reuses a session's own worktree when git's records of it name a different spelling of its path (a moved repository, or a Windows path written as `/c/Users/...` by one git and read as `C:\Users\...` by another). The launcher now runs `git worktree repair` on the slot first. Before, it removed the slot's registration as stale and then refused the checkout as "not a worktree". When a slot's registration really is gone, the refusal now says the directory is the session's own checkout and how to move it aside. It no longer tells you to `git worktree move` it into `<name>-agents/`, which is only the remedy for agent worktrees nested inside the slot.
