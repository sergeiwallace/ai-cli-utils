- A restarted agent no longer comes up with direnv's ".envrc is blocked" refusal and without its project environment. The session worktree's `.envrc` is now approved before every agent start, in the launcher after the worktree is synchronized and in the session script before the first start and every restart, for every agent CLI. Content identical to the repository root's copy or to the `.envrc` on `origin/HEAD` is approved; anything else (for example an edit the session made) stops the start with an error naming the file and the `direnv allow` command to run after reviewing it. No `direnv` or no `.envrc` still launches as before, and `AI_CLI_SKIP_DIRENV=1`, `[direnv] enabled = false` and `-D/--no-direnv` turn the approval off. Every outcome, and every line a running session's restart prints, now reaches the launch log with the time it was printed.
